# Adversarial audit — 30 October 2026

**Scope:** `10USTECH/pricelock` at `main@610d337` (v1.3.0, merge of PR #5).
**Trigger:** an external review of v1.3.0 reported two structured-data defects (a currency
change that passed, and a valid key-order variation that was refused). Before acting on it,
the maintainer asked for an independent adversarial pass: build our own attack list, run
every attack against both CI gates, and record only what reproduces.
**Method:** each probe mutated a scratch copy of the repo and ran exactly what CI runs —
`node bin/bake-prices.mjs --check` and `node --test test/parity.test.js` — and was scored
CAUGHT if either gate failed, MISSED if both passed. Network guards were probed by calling
`isBlockedAddress` on edge-case addresses; the write path by building the tree on disk.

## Baseline (before changes)

| | |
|---|---|
| Tests | 84 pass; `--check` clean on the demo |
| Gates | CI on push and PR (Node 18.17.0 / 20 / 22): `--check` (strict), `node --test`, `npm audit` |

## Findings

Severity is for this tool's threat model: an operator baking a tree they control, with CI
as the gate, and a published price a crawler reads. Every row was reproduced against
`610d337` and is now a failing-then-passing test in `test/adversarial.test.js`.

| # | Sev | Finding | Reproduced at 610d337 | Fix (v1.4.0) |
|---|---|---|---|---|
| H1 | **High** | A **symlinked directory** under `--site` is followed: Node's recursive `readdirSync` descends into it and `listHtml` only `lstat`s the final path component. `--write` rewrote `linkdir/victim.html`, a file *outside* `--site`. Contradicted the README ("symbolic links … are refused"). | yes — outside file rewritten, exit 0 | Walk the tree by hand with `lstat`; refuse links to directories and linked `.html`; every baked file's real path must lie inside `realpath(--site)`. |
| H2 | **High** | A **duplicate `"identifier"` key** in a MenuItem passes both gates. Parsers keep the last key, so a crawler reads the Dinner id at the Lunch price ($12, not $16); the baker and parity extractor read the first. Same for a duplicate `"price"`. | yes — both gates pass | `lib/jsonld.mjs` `parseStrict` refuses duplicate keys (after unescaping) in baker and parity. |
| H3 | **High** | **`priceCurrency` is never checked.** Changing it to `EUR`, or deleting it, passes both gates — a right number in the wrong currency. (Confirms the external review's P1.) | yes — both gates pass | The offer is `(identifier, price, priceCurrency)`: `--check` reports and `--write` corrects all three; the parity check compares currency to the snapshot. |
| M1 | Medium | The **unread-price detector was lexical** and bypassable. Passed both gates: a second MenuItem for a managed id with a `price` key; a Product `AggregateOffer` (`lowPrice`/`highPrice`); `&#36;1.00`; `$<span>1.00</span>`; `＄1.00`. Also unseen: microdata `itemprop="price"`, Open Graph `product:price:amount`. | yes — all pass | JSON-LD is parsed; every price-bearing key not owned by a managed offer is reported. Outside JSON-LD the detector decodes dollar entities/variants, sees through whitespace, `&nbsp;` and inline tags, and covers microdata and Open Graph. |
| M2 | Medium | **Valid JSON-LD refused** (false positives): `"name"` before `"@type"`; `"identifier"` after `"offers"`. Fail-closed, but key order is meaningless in JSON. (Confirms the external review's P2.) | yes — `--check` fails | Parsed transform: key order is irrelevant; edits touch value spans only. |
| L1 | Low | **IPv6 SSRF gaps.** Allowed: SIIT `::ffff:0:a9fe:a9fe` (metadata address), NAT64 local-use `64:ff9b:1::/48`, site-local `fec0::/10`, Teredo `2001::/32`, `192.88.99.0/24`. Reachability depends on the network; the fix is cheap. | yes — `isBlockedAddress` returned false | IPv6 must be global unicast (`2000::/3`) after unwrapping embedded-IPv4 forms; Teredo, benchmarking, ORCHID, `3fff::/20` and `192.88.99.0/24` added. |
| L2 | Low | An already-correct minified `"identifier":"X"` was rewritten as `"identifier": "X"` — churn on a page that needed no change (the README promises byte-for-byte preservation). Found by the new baseline test. | yes | Span edits: unchanged values are not rewritten. |
| L3 | Low | The Square adapter accepted a `price_money` with **no currency** and assumed the feed currency. | yes | Refused. |

### Not reproduced / held up

- Two concurrent `--write` runs over the same tree and catalog converged (same output); this
  is not a coordination guarantee — see `GUARANTEES.md`.
- Direct private, loopback, metadata (`169.254.169.254`, `fd00:ec2::254`) and redirect cases
  are refused, before the fetch and at connect time.
- CI uses a read-only token and SHA-pinned actions; required status checks are bound to the
  GitHub Actions app (integration 15368), so another app cannot satisfy them.

### Still open (documented, not fixed here)

- **Visible-side matching is a pattern**, not an HTML parser: `data-sq-item` before `class`
  is refused as unreadable (fail-closed false positive). A parse5 rewrite stays parked by
  owner ruling (2026-10-18).
- The `<script type="application/ld+json">` **boundary** is found by a pattern; a block
  inside an HTML comment is treated as live (it is baked, never trusted as a pass).
- The visible detector is lexical; prices in images, CSS `content`, script-rendered text, or
  written without a currency sign are not seen. See `GUARANTEES.md`.
- Symlink **swap races** between listing and writing; multi-file atomicity; concurrent
  bakers — unchanged, documented.
- `bypass_actors` on the `main` ruleset was not readable with the auditing token; the
  maintainer must confirm the bypass list is empty.

## Red-team of the fix (before merge)

The first v1.4 commit (`c1456e6`) was attacked again before any PR. An independent agent
was stopped early by a safety classifier with no results, so the red-team was re-run in
focused areas against scratch copies. Each row passed both gates on `c1456e6` and is now a
failing-then-passing test (`R1`–`R5` in `test/adversarial.test.js`).

| # | Sev | Bypass on c1456e6 | Fix |
|---|---|---|---|
| R1 | **High** | A live ld+json block with an entity-encoded type (`application/ld&#x2B;json`) or a padded / parameterised type was not read by either gate; with escaped keys inside, a wrong managed price passed. | Every `<script>` is found; its first `type` is decoded, trimmed and stripped of parameters as a browser does. |
| R2 | Medium | An ld+json block that is not valid JSON was skipped when its text did not literally say MenuItem/price (keys can be escaped). | Every unparseable ld+json block is refused, by the baker and by the parity extractor; deep nesting is a clean refusal. |
| R3 | Medium | A separate node sharing the managed offer's `@id` added `"priceCurrency": "EUR"` (JSON-LD merges nodes by `@id`). | `priceCurrency` outside the managed offer is reported like a price key. |
| R4 | Medium | `&#36` without `;`, a zero-width space, `&#160;`, full-width digits, and digits written as references hid a visible price. | References are decoded before matching; zero-width and full-width forms are covered. |
| R5 | Low | The R4 tag-skip pattern was quadratic: 61 s on a 400 KB page of `$<`. Found by a timing probe of the new code. | Bounded (16 tags/comments, 256 chars each): 0.26 s. |

## Result

121 tests pass (84 before; 37 added, 3 updated to the parsed behaviour: F3a now bakes the
`identifier`-after-`offers` shape instead of refusing it, and the F6 extractor tests carry
`currency` and report an identified item with no offer as `price: null` so parity fails on
it); the parity JSON-LD test now also compares currency. The demo tree bakes byte-identical.
