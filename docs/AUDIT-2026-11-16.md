# Audit — 16 November 2026

**Scope:** `10USTECH/pricelock` at `main@47b05e5` (v1.5.0), Node 22; 141 tests passing.
**Trigger:** an external hardening brief listing nine suspected gaps (P1–P3). It asked for
each to be reproduced or disproven, not assumed. It named two files that do not exist
(`lib/html.mjs`, `lib/fetch.mjs`); the code it meant is in `lib/extract.mjs` and `lib/guards.mjs`.
**Method:** each probe ran on a scratch copy — `--write` once to seal it, one mutation, then
`--check` exactly as CI runs it. Every confirmed defect is a test in
`test/audit-2026-11-16.test.js`, committed failing (15 of 22) before any fix. One of the 15
— a drafted "required `@context`" test — was withdrawn with the fix and replaced by a
control that pins today's behaviour (G3b below).

### Where the brief was wrong or overstated

- **Severities.** Nothing here is reachable remotely. G2 and G3 were rated P1; G2 fails
  closed and G3 needs someone to hand-write a foreign type. G1, rated P2, is the only one
  that destroys data.
- **G3b is not an integrity gap.** The brief asked for a required context. The check on the
  prices does not depend on it.
- **"Do not request confirmation for routine fixes"** does not fit the name check, page-level
  parity or a required context: each refuses pages that pass today.

## Fixes (v1.6.0)

| # | Fix | Why this and not more |
|---|---|---|
| G1 | `assertSnapshotTarget` (`lib/guards.mjs`), run before anything is baked, in `--check` and `--write`: `--snapshot` is refused (exit 2) when it is or resolves to the `--src` file or a page, is any `.html` path inside `--site`, or is a directory. "Resolves to" = same real path (nearest existing parent for a new file) or same device+inode. | A snapshot beside the catalog, inside the site as `.json`, or not yet existing still works (control test). No lock, no transaction layer. |
| G2 | `presentAt` treats an omitted or `null` flag as true. A location in `absent_at_location_ids` is absent whatever else is set (listed as both → skipped, reported). A non-boolean flag or a list that is not an array of non-empty strings throws. | Both stricter-than-Square rules err toward leaving an item off the menu. |
| G3 | A type is `Term`, `schema:Term` or `http(s)://schema.org/Term`, exactly. `assertPlainSchemaOrg` refuses a node `@type` from any other vocabulary — in the baker and the parity extractor, which share it. The datatype of a `@value` literal is left alone. | Refused, not ignored: ignoring would turn the node's price into an anonymous "unread" line. |
| G4 | An unresolved priced row / MenuItem is reported by name and counted with the unread prices: refused by default, `WARN` under `--allow-unread`. It is still left byte-identical and never enters the snapshot. A MenuItem with no price is left alone as before. | Reuses the existing strict default and its one opt-out. No new flag or file. |

## Behaviour changes (each fails closed)

- A priced menu row or MenuItem whose name is not a priced catalog item now stops the run.
  This includes a variable-priced catalog item printed with a price. Fix: add the item to the
  catalog, remove the price, or pass `--allow-unread` (which applies to the whole run).
- A `@type` outside schema.org on any node of any ld+json block under `--site` is refused.
- A `--snapshot` path that names an input is a usage error.
- The Square adapter now emits objects that omit `present_at_all_locations`. A feed built from
  the same catalog can gain items.

Unchanged: the feed contract, zero dependencies, byte-for-byte output on an already-correct
page (the demo tree and snapshot are untouched).

## Held for an owner ruling (not in this change)

1. **Name check for anchored ids (N1)** — opt-in, with an explicit alias file.
2. **Page-level parity** — both surfaces of an id on the same page, with stated exceptions.
3. **A parity runner for a consumer's own site and snapshot** — today a green run proves the demo.
4. **Per-item exemptions for G4** — `--allow-unread` is all-or-nothing.
5. **Required `@context` (G3b).**

## Result

163 tests pass (141 before; 22 added; no existing test changed). `bake-prices --check` on the demo:
