# Audit — 24 November 2026

**Scope:** `10USTECH/pricelock` at `main@6cf58d8` (v1.7.0), Node 22; 185 tests passing.
**Trigger:** an unsigned "engineering directive" listing seven suspected gaps (one P0, three
P1, three P2). It asked for each to be validated against HEAD, not assumed, and said its one
reproduction was done on a reconstruction, not on this repository.
**Method:** each finding was first traced in the source, then written as a test in
`test/audit-2026-11-24.test.js` and run against v1.7.0. The file was committed failing
(22 of 28; the other 6 are controls) before any fix.

## Findings

### Where the directive was wrong or overstated

- **H1 is not a P0.** Nothing is reachable remotely, the Square adapter cannot produce the
  feed shape that triggers it, and the page must carry an unanchored row. It is the most
  serious of the five because it fails open and the wrong id then persists.
- **"Catalog completeness", "source authenticity" and "publication integrity"** are not
  properties this tool can establish from a file on disk. They are listed as limits, not fixed.

## Fixes (v1.8.0)

| # | Fix | Why this and not more |
|---|---|---|
| H1 | A catalog record keeps every section it is listed under. The section tie-break picks a candidate only when exactly one is listed under the node's section; section names are compared ignoring case and spacing. The ambiguity message lists every section of each candidate. | No change to anchored ids, to the feed shape, or to the rule that the page price is never used. |
| H2 | `bake-prices --location <id>`: the catalog must be schemaVersion 2 with `locationId` exactly `<id>`, in `--check` and `--write`; a catalog that states no location is refused. | Opt-in: without the flag, behaviour is unchanged, so no existing pipeline breaks. |
| H3 | `squareToFeed` refuses a response, or a list of responses, whose last page still carries a `cursor`; a `cursor` that is not a string is refused as malformed. | Applied in the pure transform, so the live path is covered by the same rule. |
| H4 | `parseJsonStrict` (`lib/jsonld.mjs`): `parseStrict` accepts or refuses the text, then `JSON.parse` builds the value. Used for the catalog (file and URL), the Square response (`--input` and live), and the snapshot in `lib/parity.mjs`. Input nested too deeply to check is refused. | Reuses the existing strict parser; no new dependency, no second grammar. |
| H5 | A live `square-to-feed` run records `fetchedAt` (UTC ISO-8601) in the feed. The baker validates its shape, prints it, and does not copy it into the snapshot. An `--input` run records none. | Keeps the snapshot of an unchanged catalog byte-identical. No maximum-age gate: that would make `--check` depend on the clock, and is an owner decision. |

## Behaviour changes

- A feed listing one id under two sections can now be refused where it baked before (the
  fail-open case), and can bake where it was refused before (the false refusal).
- A catalog, a saved Square response, or a snapshot with a duplicate key is refused.
- A saved Square response that ends on a page with a `cursor` is refused.
- **A live `square-to-feed` feed is no longer byte-identical from one fetch to the next:** it
  differs in the `fetchedAt` line. The snapshot is unaffected and `--check` stays in sync. A
  pipeline that commits the feed file will see a one-line diff per fetch.
- A feed whose `fetchedAt` is present but not a UTC ISO-8601 timestamp is refused.

Unchanged: zero dependencies, the snapshot format, byte-for-byte output on an already-correct
page (the demo tree and snapshot are untouched).

## Not verified

- **The live Square path was not executed.** No token and no network were used. The live
  fetch shares `parseJsonStrict`, the cursor rule and `withFetchedAt` with the offline path,
  each of which is tested; the two lines that call them from the network branch are not.
- **A catalog read from a URL** uses the same `parseJsonStrict` call as a file; only the file
  branch is exercised by a test.
- Run on Node 22 only; CI runs 18.17.0 / 20 / 22.

## Limits that remain (stated in `GUARANTEES.md`)

- A saved Square response with a page missing from the middle, or given as a flat list of
  objects, cannot be shown to be incomplete offline.
- `--location` compares the command line with the feed. It does not query the POS.
- `fetchedAt` is written by whoever ran the adapter; nothing verifies it or enforces an age.
- One parser reads every surface; the deployed site is not checked.

## Held for an owner ruling (not in this change)

1. **Make the location binding the default** — for example, refuse `--write` when the
   catalog's `locationId` differs from the committed snapshot's, unless `--location` is given.
2. **A maximum catalog age** (`--max-age`) checked against `fetchedAt`.
3. **Refuse a flat object list as `--input`**, since it carries no pagination evidence.
4. **Committing the directive's standing principles** as a contributor file. Its findings
   table is recorded here instead; a dated list does not belong in a standing document.

## Result

213 tests pass (185 before; 28 added; no existing test changed). `bake-prices --check` on
the demo: exit 0, no file would change, snapshot unchanged.
